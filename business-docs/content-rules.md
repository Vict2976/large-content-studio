# Content rules the studio must hold

Every blog draft must be written as direct declarative or imperative sentences. The writer must never hedge, so words like "might", "perhaps", "maybe" and "it depends" cannot appear in a draft, its headline or its subheadings.

A draft must never contain placeholder text. Square brackets, angle brackets and fill-in markers such as "[product name]" are not allowed; the writer must commit to concrete wording.

A draft must never refer to itself or its own structure. It cannot mention the introduction, the conclusion or the call to action, and it should not announce what it is about to do.

Every blog draft should end with a direct instruction to the reader, without naming it as a call to action.

A summary must have no more than five bullet points, and each bullet must be under twenty words.

A caption must include exactly one relevant emoji and must end with a call to action.

Every request to the studio's API requires an API key in the x-api-key header. A request without one must be refused with a 401 and must never reach a model.

Otto, the agent, must always show its plan before acting on a multi-step task. It cannot send, post or publish anything without a person confirming the plan.

Translations should preserve tone and idiom, and must never add content that was not in the source.
